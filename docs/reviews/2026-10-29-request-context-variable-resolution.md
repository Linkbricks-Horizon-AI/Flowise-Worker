# VORA 요청의 대화 연결 변수 전달 보강

기준일: 2026-10-29 · WORKS-LAUNCH-203

## 원인과 수정

VORA MAIN → DOCS 허브 → WORD 실행 도구의 실제 호출에서 인증된 대화 정보를 찾지 못해 링크를 만들지 못했다. 허브의 제품별 변수 매핑 누락과, `resolveVariables`가 허용된 요청 변수를 템플릿 치환에 사용하지 않는 경로를 확인했다. `$vars`는 작업 공간 기본값 대신 현재 요청의 API 권한 검사 후 값을 사용한다. `$flow`의 워크플로우·세션 정보는 유지하고 도구 활성화·스키마·자식 워크플로우 설정은 변경하지 않는다.

`getGlobalVariable`의 변수별 허용 검사를 유지하고 치환용 기본값을 복사해 다른 노드·요청에 값이 남지 않도록 한다. Web과 Worker의 동일 함수 구간만 수정하고 서로 다른 실행기 파일은 복사하지 않았다.

## 검증

-   기존 코드에서 실제 요청 context/locale, 기본값 없는 변수, 후속 요청의 context 검사가 실패함을 재현했다.
-   수정 후 기존 API 권한·도구 ID 회귀 5개와 요청값 치환·거부·요청 격리·기본값 없는 변수 회귀 4개가 통과한다.
-   MAIN의 DOCS 허브에 4제품 context와 locale의 명시 매핑을 추가했다. 원래 generic context/source 매핑과 그 외 그래프/API 설정은 보존했다. 사용자 권한을 추가하거나 자식 도구 활성 map을 복사하지 않는다.
-   운영 배포와 실제 MAIN 호출 결과는 VORA WORD의 `docs/handoff/2026-10-29-template-fill-launch.md`에서 별도로 기록한다. 단위 검사 통과를 운영 완료로 대신하지 않는다.
